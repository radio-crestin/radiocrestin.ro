# radiocrestin.ro

## Dev Server
- Port: **3005** (`npm run dev` runs on http://localhost:3005)

## Stack
- Astro 6 (static output) with React islands (`client:load`)
- TypeScript, SCSS Modules, Zustand
- Hosting: an assets-only Cloudflare Worker `radiocrestin-ro` (`wrangler.jsonc`, output `dist/`; no `main`, so no Worker code runs and asset requests are free). Serves directory-format URLs; `scripts/generate-trailing-slash-redirects.cjs` writes `dist/_redirects` so `/x` 308-redirects to `/x/`
- API: https://api.radiocrestin.ro/api/v1/stations

## Project Structure
- `src/pages/` — Astro pages (thin shells; SEO objects + JSON-LD in frontmatter)
- `src/layouts/BaseLayout.astro` — global head: meta, Open Graph, canonical, Organization/WebSite JSON-LD
- `src/common/components/` — React components (`RadioApp`, `StatisticiApp`, etc. are page islands)
- `src/common/utils/seo.ts` — per-page SEO objects; canonical URLs use trailing slash
- `src/common/models/` — TypeScript interfaces
- `src/common/services/` — API calls (fallback to `src/common/data/fallback-stations.json`)
- `src/common/store/` — Zustand stores
- `public/icons/` — SVG icon components
- `scripts/` — build-time generators (sitemap, llms.txt, station thumbnails)

## SEO conventions
- All internal URLs use the trailing-slash form (`/radio-gosen/`) to match host redirects
- `public/sitemap.xml` and `public/station-thumbnails/` are gitignored build artifacts —
  regenerated by `npm run build` (Cloudflare build command must be `npm run build`, not `astro build`)
- Station subpages (`/recent-songs`, `/reviews`, `/adauga-recenzie`) are modal deep-links
  excluded from the sitemap; `/recent-songs` canonicalizes to the station root, while
  `/reviews` (own "Recenzii …" title, `seoStationReviews`) and `adauga-recenzie` are noindexed

## Announcements
- Home card (above "Stații favorite:" on the home and station pages, in the favourites column; top of the FAQ, Descarcă and Statistici content) + `#anunt/<slug>` page dialog + station bells/sheet (header and player): `src/common/components/Announcements/`; contract in the backend repo's announcements SPEC. The card's code is a lazy chunk (`lazy.tsx`, loaded by `gate.ts`) that hydrates the server markup. On a station's pages its own announcements lead the card, in a fixed order, instead of sitting behind its bell (`stationFirst` in `utils/announcements.ts`). Picking a station, the player's previous / next and Back change the station without a page load, so the radio pages (`RadioApp`) carry every station's announcements (`getRadioBuildSnapshot`) and the card follows the selected station, deciding again (and rotating on) as a new load would.
- No layout shift: pages fetch the list at build (`services/announcementsBuild.ts`, 2 s timeout) and server-render every item; the inline script from `utils/announcementsPrepaintScript.ts` (BaseLayout `<head>`) hides what this visitor must not see before first paint; `AnnouncementsProvider` adopts the same result after hydration. Eligibility lives in one place: `utils/announcementsPrepaint.ts`.
- Order: the API's (admin drag and drop, `position`); never re-sort. Each visit shows that order rotated to the rotation's start item (`rotateFrom`), paging stops at both ends. `settings.autoplay_seconds` > 0 turns on auto-advance (`useAutoplay.ts`) and the `.ann-stack` layout: every slide in one grid cell, so the card has the tallest slide's height from first paint.
- Clicks: `target` is `card`, `button` or `link` (a link in the description, e.g. "Donează"; PostHog also gets `link_url`).
- After load the fresh, CDN-cached list is stored in `announcements-feed` (removals apply on the next load; additions come with the next deploy). Local history (dismissed, impressions, clicks and reminder impressions for the hide rules, rotation, seen, country) is in `store/useAnnouncementsStore.ts`.
- Hide rules after clicks (`hide_after_clicks`, `impressions_after_click`, `hide_click_target`): semantics in `backend/docs/announcement-hide-rules.md`; the tests run its shared cases (`utils/announcementHideRules.test.ts`). Absent fields change nothing.
- Waits (`count_on`, `count_station_slugs`, `show_after`, `show_again_times`, `show_again_after`): the pre-paint hides one still waiting (`w`: not `started`, `waited < show_after`) and lets a hidden one through when it comes back. Per slug the store keeps `started`, `returns` and `waited` (`count_on` events while it waits; they don't count while it shows). The events: the visit (`countVisit`, counted in `view.ts` once per decision: page load, or a station change in `RadioApp`, decided as a new load would), another announcement's impression (`countImpression` with the list) and a playback (`RadioPlayer` → `playbacks.ts`, once per station started; kept in `announcements-playbacks` until the announcements code counts them). The tests replay the cases file's `show_again_cases` and `timelines`.
- Share action (`button.action.type: share`, optional `url` and `share_text`): `share.ts`, the Web Share API, else the link copied with an `.ann-notice` "Linkul a fost copiat".
- To develop against a local backend or mock, build/run with `PUBLIC_ANNOUNCEMENTS_API_BASE=http://localhost:8080/api/v1 npm run dev`. `?anunturi-preview=<token>` shows unpublished announcements.

## Stories
- Share pages `/poveste/<slug>/` (`src/pages/poveste/[slug]/`), built from `GET /api/v1/stories/` (`services/storiesBuild.ts`; contract: `backend/docs/stories-api.md`). The backend rebuilds the site when a story is published or changed; the API down means no share pages that build, never a failed build. The stories themselves show only in the app.
